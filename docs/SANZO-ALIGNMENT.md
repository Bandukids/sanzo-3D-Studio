# SANZO 3D Studio 与 SANZO Music 对齐方案

核对日期：2026-11-16。

依据：SANZO Music GitHub 仓库的首页、创作空间、Studio、共用导航、主题样式及素材管理说明，Music 线上首页的页面内容与导航；当前 3D Studio 的本地源码与浏览器实际显示。

补充访问用户提供的 https://sanzomusic.com/ 后，已成功读取并查看线上首页。首页包含探索音乐、创作空间、Studio、暂未开放的模型训练，以及数字人工作室入口；主标题、灵感输入、模板和流程介绍与此前读取的仓库结构基本一致。进入 Music 创作空间的操作超时，因此创作空间、Studio 的线上视觉和登录后状态尚未核验，相关判断仍来自仓库实现；不能把本次工具超时直接归因于网站故障。

## 本轮实施状态

2026-11-16 已完成本地改版，以下对比表记录的是改版前的差距与目标。

- 已实现独立路由：品牌首页、创作空间、资产库、Studio、任务中心、偏好与连接。
- 已统一浮动侧栏、页头、SANZO 字标与副标、冰蓝 / 琥珀玻璃界面、浅深主题；模型舞台保留中性深色。
- 已实现引擎下拉、高级参数折叠、生成按钮固定、浏览器草稿、手机参数 / 预览切换与菜单键盘操作。
- 已实现资产分组、命名、项目归属、搜索筛选排序、完整版本记录、文件下载、回收和恢复；沿用原有任务与模型文件。
- 已沿用并验证已有真实 GLB、FBX、骨架和动画片段的预览；补充异步加载竞争保护与不可见时暂停渲染。保留片段选择及播放 / 暂停，本轮未增加逐帧动画编辑或时间轴。
- 已验证隔离演示的提交 → 完成 → 预览、资产信息保存及刷新、项目筛选、回收恢复；本轮没有提交新的真实云端生成请求。
- 自动测试覆盖资产与版本逻辑、直达路由、65 条任务历史、元数据校验、持久化与恢复；上游能力的实测边界仍见 README。

浏览器核验：默认桌面 1280 × 720、布局尺寸 1440 × 900 / 1280 × 800，以及手机 390 × 844。主题、模型工具与手机版均已检查；截图位于 `output/screenshots/`。代码尚未发布到线上。

## 判断

两个产品的首页已经有明显的家族感：深蓝背景、蓝橙主视觉、玻璃输入框、大标题、灵感模板以及相似的品牌文案。3D Studio 也已经具备实际生成和连续加工的基础，并非只有展示界面。

主要差距发生在进入创作之后。Music 有独立的创作空间、统一导航、可切换的浅深主题、素材管理和持续存在的播放器；3D Studio 把介绍、创作、预览、作品和流程说明放在同一张长页面。要对齐完成度，首先应建立一致的工作空间和资产操作方式。

## 具体差距与对应改法

| 维度 | Music 仓库中的实现 | 当前 3D Studio | 对齐方向 |
| --- | --- | --- | --- |
| 页面组织 | 首页与创作、Studio、素材等工作页面分开 | 首页、创作台和作品库以页面锚点串联 | 保留品牌首页，独立创作工作台和资产库 |
| 产品外壳 | 浮动侧栏、统一页头、导航收起及手机菜单 | 顶部横向导航 | 共用 SANZO 字标、导航间距、图标、主题开关；3D 使用产品副标 |
| 工作区主题 | 默认冰蓝玻璃，另有深色主题 | 全站单一深色 | 首页保留深色，工作区支持同系浅深主题；模型舞台单独保持适合观察材质的中性底色 |
| 参数层级 | 模型下拉、基础与高级设置分层 | 五个引擎选项加完整参数直接展开 | 默认露出描述/参考图、引擎选择、生成按钮；面数和材质等进入高级设置 |
| 工作区密度 | 创作和作品在工作区内组织，播放器持续可用 | 参数、模型、管线和图库之间需要纵向滚动 | 让预览、生成按钮和主要下一步操作在常用桌面尺寸内可达 |
| 资产管理 | 搜索、筛选、工作区、命名、统一素材和回收站 | 按任务展示卡片，可打开和直接删除 | 增加名称、分类、搜索、排序、项目归属与可恢复删除 |
| 连续加工 | 作品可进入后续 Studio 操作 | 已有 parentId、阶段链和管线，但图库把阶段摊成卡片 | 把一个角色展示为一项资产，展开原始模型、绑骨和动作版本，保留各任务记录 |
| 持续操作 | 音乐结果有统一播放入口 | 预览、下载、动画切换已有，但分散在舞台上下 | 统一模型工具条和结果操作区；动画结果出现时显示时间轴和片段选择 |

## 建议的工作台

桌面默认采用三列：全局导航、创作面板、主舞台。

```text
SANZO 导航       创作面板                  3D 主舞台
──────────       ───────────────           ─────────────────────
创作空间         文生 / 图生               当前资产名称 · 当前版本
我的资产         描述 / 参考图              模型、材质、骨架与动画预览
Studio           引擎选择                  旋转 / 线框 / 骨架 / 复位
任务             高级设置（折叠）           建模 → 绑骨 → 动画
设置             开始生成（固定可见）       下载 / 继续加工 / 版本
```

- 导航宽度约 200–212 px，创作面板约 320–360 px，剩余空间优先交给模型。
- 资产库成为独立视图；创作时可从抽屉选取已有资产，不再滚动到页面底部找作品。
- 在较窄桌面上收起导航或把参数切成抽屉；手机使用“参数 / 预览 / 资产”切换，避免把完整桌面多列缩小。
- 宽屏才考虑常驻右侧属性栏，常规屏幕使用抽屉，保证模型有足够观察面积。
- 3D 中对应 Music 播放器的核心，是持续可用的模型舞台与操作栏。动画时间轴仅在结果确实包含动画时出现。

## 3D 应保留的专属设计

1. 首页蓝橙形体与线框可以保留，但减少过强的发光、装饰网格和抢占注意力的动态，让输入和作品更突出。
2. 模型、骨架、材质和动画是不同结果，应显示实际具备的能力和文件格式。
3. 角色的一条加工链采用资产版本呈现，例如“蓝衣男孩 / 原始模型 → 绑骨 → 行走”。重新绑骨或更换动作产生分支版本，保留来源。
4. 人形动作模板、Tripo 图生 URL 限制以及来源任务时效，应在对应操作处解释，并及时禁用不满足条件的动作。文生动作产生独立标准人形动画，应作为独立创作能力展示。
5. 减面、UV、纹理重做与格式转换尚未接入，等真实服务接通后再开放操作。

## 实施顺序与验收

### 第一轮：工作台与视觉统一

交付：品牌首页、独立创作空间、统一侧栏与页头、浅深主题、基础/高级参数、主要结果工具条。

优先涉及 `public/index.html`、`public/css/style.css`、`public/js/main.js`。可以抽出主题、外壳与页面路由模块，沿用现有 Three.js Viewer 和后端 API。

验收：从首页输入的描述或参考图能带入创作空间；在 1440 × 900 与 1280 × 800 下，主要生成和结果操作可达；不因上下找作品丢失当前模型；手机无横向溢出；切换主题后控件、模型和文字保持清晰。

### 第二轮：资产与任务的完整体验

交付：资产重命名、搜索、类型/状态筛选、项目分组、版本链、回收站，以及统一任务列表和完成提示。

需要在 `server.mjs` 增加资产元数据与软删除接口；前端复用既有 `parentId` 和任务状态，不把“任务”和“资产版本”混为同一概念。

验收：同一角色不同阶段归属正确；刷新后任务仍能找到；生成和查询失败分别提示；删除失败时卡片保留并显示原因；回收恢复保留关联；任何不明确的提交结果不自动重复扣费。

### 第三轮：真实能力与运行可靠性

交付：逐项验证尚未实测的模型路径；完善本地模型导入和长期资产再加工的服务方案；按部署目标补充账号、存储和备份。

目前服务只监听本机，JSON 存储可以支撑本地原型；若要成为多人站点，应引入用户身份、资产权限与合适的数据库/文件存储。浏览器不应直接拿到服务端密钥。

验收：将演示、接口已接通、真实调用已验证三种状态明确区分；不同用户数据隔离；历史任务和模型文件可备份恢复。云端路径的真实验证另按所选服务额度进行。

## 这次发现的细节问题

- 作品库有一条历史标题已经乱码，需要允许重命名并核查原始保存编码。不能据此断言当前全部文本生成链都有编码问题。
- 当前删除逻辑吞掉 API 错误后仍移除前端卡片，会产生删除成功的错觉；应等服务端成功后更新，失败则保留作品。
- 顶部“TokenHub 已连接”来自服务端是否存在 Key，而真正的鉴权验证需要点击执行。建议区分“已配置”和“验证通过”，避免把配置状态当作服务状态。
- 已有模型的 GLB 预览可正常加载，后续应在此基础上优化布局；无需为视觉改版先替换渲染器。
